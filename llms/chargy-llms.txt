# char.gy

> char.gy is a British public electric-vehicle charge point operator that puts the charger inside the lamp post, serving the roughly 40% of UK households with no off-street parking. It publishes a genuinely open, genuinely anonymous OCPI-shaped Locations and Tariffs feed because Part 4 regulation 10(5) of the Public Charge Point Regulations 2023 requires charge point reference and availability data to be published free of charge, machine readable, and without any requirement to agree to terms and conditions. There is no developer portal, no consumer API and no OAuth server; the commercial OCPI roaming interface is partner-only.

Generated by API Evangelist on 2026-07-27 from live probes and the catalog. char.gy publishes no llms.txt of its own (https://char.gy/llms.txt returns 404).

## APIs

- [char.gy Open Charge Point Data API](https://help.char.gy/support/solutions/articles/77000576948-public-charge-point-regulations-2023): Statutory open data feed at https://char.gy/open-ocpi — two read-only, unauthenticated OCPI modules. `GET /open-ocpi/locations` returned HTTP 200 anonymously with an x-total-count of 5,409 on 2026-07-27; `GET /open-ocpi/tariffs` returned 3 tariff objects. Pagination is limit/offset with x-total-count, x-limit and an RFC 5988 Link rel="next" header; date_from and date_to filter on last_updated and are verified working.
- [char.gy OCPI CPO Roaming API](https://char.gy/us/partners): Commercial Open Charge Point Interface implementation in the Charge Point Operator role at https://char.gy/ocpi/cpo. Undocumented and credential-gated — anonymous requests return HTTP 401 with `www-authenticate: Token realm="OCPI"`. OCPI 2.2.1 and 2.1.1 are supported; 2.2 is rejected with status_code 3002. Access requires a commercial roaming agreement and an OCPI credentials handshake.

## Notes for agents

- Send no credential to https://char.gy/open-ocpi — it is anonymous by law.
- Check `status_code == 1000` on every response; client errors are delivered with HTTP 200.
- There is no spatial or status filter and no per-object read; geographic questions require crawling all 5,409 locations. Use `date_from` for incremental syncs.
- `evse.status` values `WORKING` and `FAULTED` are not OCPI 2.2.1 values — do not validate them against the OCPI enumeration.
- No rate limit is published or signalled. Keep concurrency low; there is no status page if you cause a problem.
